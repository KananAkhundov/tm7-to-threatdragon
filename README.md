# tm7-to-threatdragon

Convert [Microsoft Threat Modeling Tool](https://learn.microsoft.com/en-us/azure/security/develop/threat-modeling-tool) (`.tm7`) files to [OWASP Threat Dragon](https://owasp.org/www-project-threat-dragon/) 2.x JSON.

The converter keeps the diagram (elements, data flows, trust boundaries) and the threats that the Microsoft tool generated, so you can continue working on an existing model in Threat Dragon instead of rebuilding it by hand.

Pure Python, standard library only. No dependencies.

## Usage

```bash
python3 tm7_to_json_for_threat_dragon.py model.tm7 -o model.json
```

If `-o` is omitted, the output is written next to the input as `model.json`.

Then open the JSON file in Threat Dragon (Open an existing threat model) and review it.

The script prints a summary and a list of warnings, for example:

```
Converted model written to: model.json
Diagram cells: 23
Threats attached: 115

Review warnings:
  - Unknown element type '...' ('ADFS') mapped to a process.
```

## What gets converted

| Microsoft Threat Modeling Tool | Threat Dragon |
|---|---|
| Process | Process |
| Data store | Store |
| External interactor | Actor |
| Data flow | Flow (with routing handle, protocol and encryption flag) |
| Trust boundary (box) | Trust boundary box (with contained elements and crossing flows) |
| Trust boundary (line) | Trust boundary curve |
| Generated threat (title, description, STRIDE category) | Threat on the same flow |
| Threat priority | Severity |
| Threat state `Mitigated` | Status `Mitigated` |
| Threat state `AutoGenerated` / other | Status `Open` |
| Threat state information | Mitigation text |

In the `.tm7` format, threats are generated per data flow (source, flow, target), so after conversion the threats are attached to the flows, not to the processes or data stores themselves.

## Known limitations

- **Tested on a small number of models.** It was developed and checked against one real model (7 elements, 13 flows, 115 threats). Other models may expose cases it does not handle.
- **Only the first diagram is converted.** A `.tm7` file with several diagrams will lose the others.
- **Custom stencils become generic processes** and the script prints a warning (for example, a custom "ADFS" element).
- **Trust boundary crossing is calculated only for box boundaries**, by checking whether the source and target element centres are inside the box. Line boundaries are copied as curves without this metadata.
- **Layout is approximate.** Positions and sizes come from the `.tm7`, but connector routing may look different in Threat Dragon.
- **Not converted:** notes, custom threat templates (knowledge base), validations and other tool settings.
- **IDs are regenerated on every run.** Converting the same file twice gives different cell and threat IDs.
- **Status and severity values** are mapped to the values I saw working in Threat Dragon. Other versions may expect different strings. Please open an issue if the import fails.

Always review the converted diagram and threats in Threat Dragon before relying on them.

## Tested with

- Threat Dragon: 2.6.2 (output format `2.6.2`)
- Python: 3.14.7

## How it was built

Written for a university threat modelling course project, with AI assistance, and tested and debugged against real Threat Modeling Tool output.
